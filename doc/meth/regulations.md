Вот обновленная пошаговая инструкция для вашей команды, адаптированная под работу через VS Code на разных операционных системах.

Регламент совместной работы над ТЗ проекта RubberDuck

Все изменения в техническое задание (SRS) вносятся строго через Pull Requests (PR). Главная ветка main защищена от прямой записи.

🛠️ Раздел 1. Инициализация проекта (Выполняет РП — hangmeter)


1.1. Создание репозитория на GitHub

1. Перейдите на GitHub и создайте публичный или приватный репозиторий с именем RubberDuck.
2. При создании поставьте галочку Add a README file и выберите Add .gitignore (например, для Node.js, Python или вашего стека).
3. Перейдите в Settings (Настройки репозитория) → Collaborators → Add people.
4. Введите никнейм ВП (Serlysenko) и отправьте приглашение. Serlysenko должен принять его на своей почте или на GitHub.

1.2. Настройка защиты ветки main

Чтобы никто не мог случайно запушить изменения в обход PR:
1. В настройках репозитория перейдите в раздел Branches (Ветки).
2. Нажмите Add branch ruleset.
3. Назовите правило (например, Protect main).
4. В блоке Target branches выберите Include default branch (или укажите main вручную).
5. В списке правил включите галочку Require a pull request before merging (Требовать PR перед слиянием).
6. Нажмите Save changes.

1.3. Подготовка структуры в VS Code (Debian)

1. Откройте терминал на вашей системе Debian.
2. Склонируйте репозиторий:
git clone https://github.com/Hangmeter/rubberduck.git
3. Откройте папку в VS Code. Создайте в корне файл SRS.md (файл ТЗ в формате Markdown).
4. Напишите базовую структуру (например: # ТЗ проекта RubberDuck, ## 1. Ворота MVP).
5. Закоммитьте и отправьте в main:bash
git add SRS.md
git commit -m "chore: инициализация файла SRS"
git push origin main
Используйте код с осторожностью.

📄 Раздел 2. Воркфлоу Владельца Продукта (ВП — Serlysenko, Windows + VS Code)

ВП работает в Windows. Для интеграции с Gemini и GitHub в VS Code рекомендуется установить расширения GitHub Pull Requests and Issues и любое расширение для работы с Markdown (например, Markdown All in One).

Шаг 2.1. Подготовка рабочего пространства (Один раз)

1. Установите Git для Windows и авторизуйтесь в VS Code под своим аккаунтом GitHub.
2. Склонируйте репозиторий RubberDuck через VS Code (Ctrl+Shift+P → Git: Clone) и откройте папку проекта.

Шаг 2.2. Создание ветки под новую фичу

Перед написанием требований всегда создавайте новую ветку:
1. В левом нижнем углу VS Code нажмите на имя ветки main (или нажмите Ctrl+Shift+P → Git: Create Branch...).
2. Введите понятное название ветки, например: feature-auth-srs.

Шаг 2.3. Работа с требованиями и Gemini

1. Сформируйте логику фичи в бесплатной веб-версии Gemini.
2. Откройте файл SRS.md в VS Code.
3. Перенесите сгенерированный и отредактированный текст в нужный раздел файла SRS.md.

Шаг 2.4. Фиксация изменений и отправка на GitHub

1. Перейдите во вкладку Source Control (Ctrl+Shift+G) в левой панели VS Code.
2. Нажмите + напротив файла SRS.md, чтобы добавить его в индекс (Stage Changes).
3. В поле сообщения напишите понятный текст (например: feat: описал требования к авторизации для MVP).
4. Нажмите кнопку Commit.
5. Нажмите кнопку Publish Branch (или Sync Changes), чтобы отправить ветку на GitHub.

Шаг 2.5. Создание Pull Request

1. После публикации ветки VS Code сам предложит создать PR (появится всплывающее окно или кнопка во вкладке Source Control).
2. Нажмите Create Pull Request.
3. В названии PR укажите суть (например, «Требования к авторизации»). В описании добавьте: @hangmeter, привет! Проверь, пожалуйста, логику MVP.
4. Нажмите Create.

💻 Раздел 3. Воркфлоу Разработчика / РП (hangmeter, Debian + VS Code)

Ваша задача — ревьюить код/документы, давать обратную связь и принимать изменения в main.

Шаг 3.1. Получение уведомления и ревью

1. Вы получите уведомление на GitHub или увидите новый PR прямо в VS Code во вкладке GitHub (если установлено расширение GitHub Pull Requests).
2. Откройте PR. Перейдите во вкладку Files Changed (Измененные файлы), чтобы увидеть разницу (что именно добавил или изменил Serlysenko).

Шаг 3.2. Обсуждение и доработки

• Если есть вопросы: Выделите строчку в файле прямо в интерфейсе VS Code/GitHub, нажмите значок комментария + и напишите: «Здесь логика слишком сложная для MVP, давай упростим?».
• Действия ВП (Serlysenko): ВП видит комментарий, исправляет текст в этой же ветке у себя в VS Code, делает новый Commit и Push. PR обновится автоматически.

Шаг 3.3. Слияние (Merge)

1. Когда ТЗ полностью согласовано, вы (или Serlysenko после вашего текстового "ОК") нажимаете кнопку Merge Pull Request → Confirm Merge.
2. Ветка с фичей удаляется на GitHub. Изменения теперь официально находятся в main.

Шаг 3.4. Обновление локального репозитория

После слияния вернитесь в свой VS Code на Debian и обновите локальную копию:
1. Переключитесь на ветку main (если уходили с нее).
2. Выполните Git Pull (Ctrl+Shift+P → Git: Pull), чтобы забрать утвержденные требования в свою рабочую среду и начать писать под них код.
