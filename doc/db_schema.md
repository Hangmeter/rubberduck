# Схема данных PostgreSQL (Aikiduck)

Источник схемы — [init.sql](../init.sql). База хранит сессии чекина: состояние пользователя, понимание его защитной функции и небольшие действия.

## Перечисление `emotion_type`

Тип ENUM ограничивает каждый элемент массива `session_states.emotion` десятью значениями. Другие значения база не принимает.

| Значение | Смысл |
| --- | --- |
| `ANXIETY` | Тревога |
| `GUILT` | Вина |
| `SHAME` | Стыд |
| `FATIGUE` | Усталость, когнитивное истощение |
| `CHAOS` | Мысли скачут, трудно удержать внимание |
| `AVERSION` | Нежелание заниматься конкретной задачей, скука |
| `APATHY` | Апатия, нехватка побуждения к действию |
| `IRRITATION` | Раздражение, протест |
| `FROZEN` | Оцепенение, ступор |
| `PERFECTIONISM` | Страх сделать неидеально или получить оценку |

## Общие обозначения

- **PK** — первичный ключ: уникальное значение, которое не может быть `NULL`.
- **FK** — внешний ключ: ссылка на запись другой таблицы.
- **NULL допустим** — поле может не содержать значения.
- **Нет** в столбце «По умолчанию» — явный DEFAULT не задан.
- `SERIAL` — сокращение PostgreSQL для `INTEGER NOT NULL` со значением по умолчанию из последовательности (`nextval(...)`).
- `TIMESTAMP WITH TIME ZONE` (`TIMESTAMPTZ`) хранит момент времени; его отображение зависит от часового пояса соединения.

## Таблицы

### `sessions` — сессии чекина

Каждая запись обозначает отдельный чекин пользователя.

| Поле | Тип | Ключи | NULL допустим | По умолчанию | Назначение |
| --- | --- | --- | --- | --- | --- |
| `id` | `SERIAL` → `INTEGER` | PK | Нет | Следующее значение последовательности `sessions_id_seq` | Идентификатор сессии |
| `created_at` | `TIMESTAMP WITH TIME ZONE` | — | Да | `CURRENT_TIMESTAMP` | Время создания сессии |

Индекс: `sessions_pkey` — уникальный B-tree по `id`, автоматически создаётся для PK.

### `session_states` — состояние пользователя

Хранит выбранные состояния и необязательное описание того, что происходит с пользователем.

| Поле | Тип | Ключи | NULL допустим | По умолчанию | Назначение |
| --- | --- | --- | --- | --- | --- |
| `session_id` | `INTEGER` | PK; FK → `sessions(id)` | Нет | Нет | Сессия, к которой относится состояние |
| `emotion` | `emotion_type[]` (массив ENUM) | — | Нет | Нет | Выбранные состояния из десяти доступных |
| `user_text` | `TEXT` | — | Да | Нет | Свободное описание состояния |
| `updated_at` | `TIMESTAMP WITH TIME ZONE` | — | Да | `CURRENT_TIMESTAMP` | Временная отметка записи состояния |

На одну сессию может приходиться не более одной записи состояния: `session_id` одновременно является PK и FK. Удаление сессии удаляет её состояние (`ON DELETE CASCADE`).

API принимает от 1 до 4 уникальных состояний в поле `emotions` и сохраняет их в массив `emotion`. Размер массива и уникальность проверяются JSON Schema Fastify; сама SQL-схема не ограничивает количество элементов. Повторное сохранение через API заменяет состояния и `user_text`, явно обновляя `updated_at`.

Индекс: `session_states_pkey` — уникальный B-tree по `session_id`, автоматически создаётся для PK.

### `session_insights` — понимание защитной функции

Хранит описание того, чего пользователь избегает и как текущее состояние помогает ему защищаться.

| Поле | Тип | Ключи | NULL допустим | По умолчанию | Назначение |
| --- | --- | --- | --- | --- | --- |
| `session_id` | `INTEGER` | PK; FK → `sessions(id)` | Нет | Нет | Сессия, к которой относится инсайт |
| `avoided_fear` | `TEXT` | — | Нет | Нет | Чего пользователь боится или избегает |
| `protective_func` | `TEXT` | — | Нет | Нет | Как состояние защищает пользователя |
| `updated_at` | `TIMESTAMP WITH TIME ZONE` | — | Да | `CURRENT_TIMESTAMP` | Временная отметка записи инсайта |

На одну сессию может приходиться не более одной записи инсайта. Удаление сессии удаляет её инсайт (`ON DELETE CASCADE`).

Индекс: `session_insights_pkey` — уникальный B-tree по `session_id`, автоматически создаётся для PK.

### `micro_actions` — микро-действия

Хранит небольшие действия, выбранные в рамках сессии, и отметку их выполнения.

| Поле | Тип | Ключи | NULL допустим | По умолчанию | Назначение |
| --- | --- | --- | --- | --- | --- |
| `id` | `SERIAL` → `INTEGER` | PK | Нет | Следующее значение последовательности `micro_actions_id_seq` | Идентификатор действия |
| `session_id` | `INTEGER` | FK → `sessions(id)` | Нет | Нет | Сессия, к которой относится действие |
| `action_text` | `TEXT` | — | Нет | Нет | Описание микро-действия |
| `is_completed` | `BOOLEAN` | — | Нет | `FALSE` | Выполнено ли действие |
| `created_at` | `TIMESTAMP WITH TIME ZONE` | — | Да | `CURRENT_TIMESTAMP` | Время создания действия |

У сессии может быть несколько действий. Удаление сессии удаляет все её действия (`ON DELETE CASCADE`).

Индексы:

- `micro_actions_pkey` — уникальный B-tree по `id`, автоматически создаётся для PK.
- `idx_micro_actions_session` — неуникальный B-tree по `session_id`, явно создан в `init.sql` для поиска действий сессии.

## Связи и особенности схемы

| Родительская таблица | Дочерняя таблица | Записей на одну сессию |
| --- | --- | --- |
| `sessions` | `session_states` | От 0 до 1 |
| `sessions` | `session_insights` | От 0 до 1 |
| `sessions` | `micro_actions` | От 0 до нескольких |

Дочерняя запись всегда ссылается на существующую сессию. Наличие состояния или инсайта не является условием для добавления микро-действия: все три таблицы связаны непосредственно с `sessions`.

`CURRENT_TIMESTAMP` задаётся по умолчанию при вставке записи. Поля `updated_at` не обновляются автоматически при изменениях: триггеров для этого в `init.sql` нет. Для всех временных полей разрешён явный `NULL`.

Поля `TEXT` не имеют ограничений длины или запрета пустой строки на уровне этой схемы. `NOT NULL` запрещает только отсутствие значения.

## Обновление существующей базы

`init.sql` выполняется контейнером PostgreSQL только при создании пустого хранилища. Для существующей базы переход от одного состояния к массиву выполняется отдельно, до запуска новой версии бэкенда:

```sql
ALTER TABLE session_states
    ALTER COLUMN emotion TYPE emotion_type[]
    USING ARRAY[emotion];
```

Каждое ранее сохранённое состояние становится массивом из одного элемента. Команда предназначена только для старого типа `emotion_type`; повторно к массиву её применять не нужно.
